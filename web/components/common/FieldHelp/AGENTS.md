# FieldHelp（字段说明问号）

## 一句话职责

- 给「标签本身说不清含义」的表单字段提供一个问号，hover 显示一段结构化说明。

## Source of Truth

- 说明文案由**调用方**提供（通常来自 i18n），组件不持有任何文案。
- 文案是**一个纯字符串**，结构靠约定：`\n\n` 分段、`- ` 起头成列表、`**粗体**` 与 `` `代码` `` 内联。解析规则在 `parseHelpText.ts`，它是事实源，组件只是渲染它。

## 何时用它 / 何时不用

**用**：标签说不清字段含义时——「推理参数映射」「模型能力」「输入类型」都需要一句「允许什么值、为什么、注意什么」。

**不用**：标签已经说清时——「上下文窗口」「名称」「API Key」。给每个字段都挂问号会让界面变吵，也稀释了真正需要解释的那几个。

> 判据：**遮住说明，只看标签，用户能填对吗？** 能 → 不要问号；不能 → 加。

## 核心设计决策（Why）

- **文案存纯字符串，不存 JSX。** 上游产品（如 ZCode）的官方帮助文案就是这种带 `**` 和 `- ` 的纯文本，逐字取用才能保证与官方文档一致。若改成 JSX，每次同步官方文案都要手工转写，必然漂移。
- **只认粗体与行内代码，不解释 HTML / 链接。** 输入是翻译字符串，不是用户内容，没有转义需求；支持更多标记只会扩大注入面而没有收益。
- **用 `Tooltip` 而不是 `Popover`。** 内容是单段短文本；需要手动关闭的浮层比它解释的东西还重。
- **图标在 label 旁边，不在 label 里面。** 点击 label 仍要能聚焦控件；且读屏读字段名时不应把整段说明一起读出来——图标自己带 `aria-label`，说明仍可达。

## 易错点（Gotchas）

- **不要把文案直接丢给 `Tooltip title={字符串}`。** 会渲染成一整行：`\n` 不换行、`**` 原样显示。必须走 `HelpContent`（组件已处理，但自建 Tooltip 时容易踩）。
- **宽度限制设在 `container` 上，不是 `root`。** antd 6 的 `styles.root` 是定位外层，`styles.container` 才是带内边距的内容盒；设在 `root` 上会让内边距落在 360px 之外。
- **`parseHelpText` 的分段依赖空行。** 文案里一个换行是段内换行（渲染成 `<br>`），两个换行才分段——改文案时把 `\n\n` 删掉会静默变成一行。
- **列表块要求**每一行**都以 `- ` 开头。** 混入一行不带 `- ` 的，整块会退化成段落。

## 跨模块依赖

- `parseHelpText.ts` 是纯函数，**有独立测试**（`web/test/components/common/FieldHelp/parseHelpText.test.ts`），改解析规则先跑它。
- 使用方：`web/features/coding/zcode/components/ZcodeModelFormModal.tsx`（`labelWithHelp`）。共享的 `components/common/ModelFormModal/` 尚未接入——接入时按同样方式传 `help` 文案即可。

## 最小验证

- hover 问号：说明按段落与列表渲染，`**粗体**` 是粗体、`` `代码` `` 是等宽，**不是**原样显示星号与反引号。
- 点击标签文字：输入框获得焦点（图标没有抢走 label 的关联）。
- 键盘 Tab 到图标：说明可展开（antd Tooltip 默认支持 focus 触发）。
- 长文案：宽度停在 360px 内，不横跨整个窗口。

## 何时更新本文件

- 新增支持的标记（如斜体、链接）时：先确认确实有上游文案需要它，再更新 `parseHelpText.ts`、本文件与测试。
- 若某个 CLI 需要在说明里放交互元素（按钮、链接），那说明它不该用 `FieldHelp`——换 `Popover` 并在此登记理由。
